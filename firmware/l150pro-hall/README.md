# L150 Pro 霍尔版 APP 指令超时停车

STM32 在原厂 100 Hz 底盘控制任务中检查 APP 运动指令。收到新的方向或转向指令后开始计时。若 300 毫秒内没有续发，清空方向和转向目标，由原来的轮速闭环执行停车。停车指令在下一次控制循环生效。退出 APP 模式时丢弃旧指令。原厂 PS2 手柄和轮速上报沿用各自的数据路径。

UART 和 DMA 接收中断只更新指令计数。FreeRTOS 时钟在控制任务中读取，避免高优先级接收中断调用 RTOS 接口。

## 构建

使用已适配 Arm Compiler 6.24 的霍尔编码器版工程，在仓库根目录运行：

```powershell
node firmware/l150pro-hall/prepare-watchdog.mjs 'D:/path/to/L150Pro-Hall-AC6'
```

脚本将工程复制到 `sentinel/logs/L150Pro-Hall-AC6-Watchdog-F407VE`，并按实车 STM32F407VET6 配置 512 KiB Flash。在 Keil 中打开副本的 `USER/WHEELTEC.uvprojx`，对 `FreeRTOS` 目标执行 Rebuild。产物在 `OBJ/L150Pro-F407VET6-APP-Watchdog.hex`。

## 架空验收

1. 确认实车 MCU 型号和原固件启动地址，保留原固件及恢复方法。本车确认使用 STM32F407VET6，UART1 只读备份显示原始启动向量位于 `0x08000000`。新镜像使用相同的启动地址。
2. 烧录适配板卡的镜像后，把四轮架空。先验证原厂手柄和轮速反馈，再以 0.10 m/s 的目标做短时 APP 运动。连续发送方向指令时保持低速，停止续发后观察两路轮速是否归零。
3. 核对显式停车、指令超时和蓝牙断开三个场景。记录最后一条有效指令后轮速归零的实测时间。恢复连接后先检查轮速保持为零，再给出新指令。手机 APP 长按方向键的表现也要验证。

300 毫秒是车端撤销速度目标的超时值。实车轮速归零时间还取决于控制周期和底盘制动。

## 车载雷达静止测距

在构建命令末尾加 `--radar-preview` 生成工程副本，构建后的镜像是 `sentinel/logs/L150Pro-Hall-AC6-Watchdog-F407VE-Radar-Grouped/OBJ/L150Pro-F407VET6-Radar-Multitarget-Grouped.hex`。这个版本保留 APP 超时停车，从通过校验的原厂 UART5 数据中提取车头 ±20°、0.10–2.00 m 内的障碍组。限制回波组数量前，先合并相隔约 5 cm 内的碎片，保留组内前向距离最短的点。超过六组时上报最近的六组。

蓝牙以 5 Hz 发出 `{RM序号:采样时刻毫秒:目标数[:距离毫米:方位百分之一度…]}$`。目标数 `-1` 表示暂无完整扫描，`0` 表示有效的空扫描，`1–6` 表示后面附有对应数量的距离和方位。采样时刻是控制任务观察新扫描时的 STM32 开机计时。电脑端用收到报文的时间与其他观测对齐。后端也兼容旧版单目标报文。

电脑端也会合并同帧相隔 5 cm 内的近邻回波，包含上一版多目标固件的报文。固件升级后，碎片在车端就会合并，为同一扫描中的其他目标留出上报名额。
