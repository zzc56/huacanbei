# L150 Pro 霍尔版 APP 指令超时停车

STM32 在原厂 100 Hz 底盘控制任务中检查 APP 运动指令。收到新的方向或转向指令后开始计时。若 300 毫秒内没有续发，清空方向和转向目标，由原来的轮速闭环执行停车。停车指令在下一次控制循环生效。退出 APP 模式时丢弃旧指令。原厂 PS2 手柄和轮速上报沿用各自的数据路径。

UART 和 DMA 接收中断只更新指令计数。FreeRTOS 时钟在控制任务中读取，避免高优先级接收中断调用 RTOS 接口。

## 构建

使用已适配 Arm Compiler 6.24 的霍尔编码器版工程，在仓库根目录运行：

```powershell
node firmware/l150pro-hall/prepare-watchdog.mjs 'D:/path/to/L150Pro-Hall-AC6'
```

脚本将工程复制到 `sentinel/logs/L150Pro-Hall-AC6-Watchdog-F407VE`，并按实车 STM32F407VET6 配置 512 KiB Flash。在 Keil 中打开副本的 `USER/WHEELTEC.uvprojx`，对 `FreeRTOS` 目标执行 Rebuild。产物在 `OBJ/L150Pro-F407VET6-APP-Watchdog.hex`。

## 架空验收

1. 确认实车 MCU 型号和原固件启动地址，保留原固件及恢复方法。本车确认使用 STM32F407VET6，UART1 只读备份显示原始启动向量位于 `0x08000000`。新镜像使用相同的启动地址。
2. 烧录适配板卡的镜像后，把四轮架空。先验证原厂手柄和轮速反馈，再以 0.10 m/s 的目标做短时 APP 运动。连续发送方向指令时保持低速，停止续发后观察两路轮速是否归零。
3. 核对显式停车、指令超时和蓝牙断开三个场景。记录最后一条有效指令后轮速归零的实测时间。恢复连接后先检查轮速保持为零，再给出新指令。手机 APP 长按方向键的表现也要验证。

300 毫秒是车端撤销速度目标的超时值。实车轮速归零时间还取决于控制周期和底盘制动。

## 车载雷达静止测距

车端已烧录并通过逐字节读回校验的版本见 [Radar-Compact-25m HEX](releases/L150Pro-F407VET6-Radar-Compact-25m.hex)。

在构建命令末尾加 `--radar-preview` 生成工程副本，构建后的镜像是 `sentinel/logs/L150Pro-Hall-AC6-Watchdog-F407VE-Radar-Compact-25m/OBJ/L150Pro-F407VET6-Radar-Compact-25m.hex`。这个版本保留 APP 超时停车，从通过校验的原厂 UART5 数据中提取车头 ±20°、0.10–25.00 m 内的回波。轮趣手册给出的 N10P 测距半径为白色物体 25 m、黑色物体 11 m。小物体的实际探测距离还取决于材质、尺寸、扫描高度及是否被遮挡。[轮趣产品手册](https://www.worldrobotconference.com/uploads/exfile/video/sqnfrt.pdf)

连续且深度接近的扫描点组成一个障碍组。连续三段及以上、相邻间隙和深度差均在 20 mm 内的紧邻回波，会在选取最近六组之前合并。合并后用回波覆盖的中心方位和最短前向距离上报。两个物体能否分开取决于扫描平面内是否有可辨认的间隙或深度变化。

蓝牙以 5 Hz 发出 `{RN序号:采样时刻毫秒:目标数[:距离毫米:方位百分之一度…]}$`。目标数 `-1` 表示暂无完整扫描，`0` 表示有效的空扫描，`1–6` 表示后面附有对应数量的距离和方位。采样时刻是控制任务观察新扫描时的 STM32 开机计时。电脑端用收到报文的时间与其他观测对齐。烧录后使用能读 `RN` 的新版 Sentinel 后端和网页。新版后端也能读取旧版 `R` 和 `RM` 报文。

车载雷达列表和雷达风险场使用同一个跟踪位置，抑制 15 mm 内的位移。15 cm 内已跟踪的目标偶尔出现多个相近回波时，平台用三次新扫描确认分裂。停车判断继续使用当前扫描的测量值。实车验收时先将 Motor 拨到 OFF，用纸箱、球、水瓶和两腿分别检查。对单个障碍观察目标数和位置，再把两个障碍逐步靠近，记录扫描仍能分辨两者时的间距。最后按物体分别记录最远连续识别距离。
