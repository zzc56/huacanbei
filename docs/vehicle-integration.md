# L150 Pro 四驱版风险场移植

固定摄像头的地面观测和车载雷达的障碍观测经时间校验、坐标变换与一对一匹配后，共用一张 SENTINEL 风险场。小车控制页连接 L150 Pro，显示实拍画面、车载雷达回波、风险场和编码器轮速。

## 电脑端联调

启动 Sentinel 后，在实时连接或历史回放的任意监控视图中，点击页头 SENTINEL 标志右侧的「切换实体小车」。小车页面的「返回总览」回到进入前的实时监控或历史回放。也可用 `node sentinel/launch.mjs vehicle` 直达小车控制。控制页通过 `/api/vehicle/drive` WebSocket 连接实车串口和发送键盘命令。收到有效反馈并启用测试档后，方向键才会发送运动指令。页面失焦、隐藏或离开时停车，后端在 250 毫秒未收到方向指令或心跳时撤销运动。

### 查看实体小车轮速

在 Windows 中配对小车的 `WHEELTEC` 蓝牙，确认对应的出站串口。启动 `vehicle` 模式后，进入“小车控制”，在“实车编码器”卡片点击“连接 COM11”。这个串口号来自本次实车联调。其他电脑可在启动前设置 PowerShell 环境变量 `$env:SENTINEL_VEHICLE_PORT = 'COMx'`，替换为本机的出站串口。

断开手机 APP 的蓝牙连接后，可用原厂手柄测试。卡片读取原厂上报的 A、B 两路轮速大小和电量，反馈超时时会清空旧读数。点击“断开串口”或离开控制页会释放串口。连接后默认读取遥测，启用测试档后可用键盘控制。

### 静止检查车载雷达

烧录 [25 米车载雷达固件](../firmware/l150pro-hall/README.md#车载雷达静止测距) 后把 Motor 拨到 OFF，保持小车静止。在「小车控制」连接 COM11，两个检测模式的「车载雷达实测」都显示前向 ±20°、0.10–25 米软件量程内最多 6 个障碍组。把障碍物放在扫描高度，对照页面上的目标数、距离和角度。先连续观察单个目标，再加入第二个目标并逐步缩小间距。分别记录不同障碍物可稳定识别的最远距离。

量程内无回波、没有完整扫描和接收超时分别显示。旧回波超时后从画面清除。该页面用实测回波核对距离与方向，实车位姿、风险融合和行驶限速要在后续联调中接上。

### 0.40 m/s 实车最终测试

使用经过车端超时停车验证的固件，在空直道对准一个静止纸箱。切到 APP 控制模式，打开「小车控制」并连接 COM11。两路轮速归零且雷达扫描在线后，点击「启用最终测试」。车端确认 0.40 m/s 后，按住 W 或 ↑ 前进，松键或按空格停车。

风险场判断行驶通道内的最近障碍前向距离 **小于或等于 40 cm** 时，后端自动下发停车，持续按住 W 也会停车。纸箱移开后，松开再重新按 W 才能前进。雷达超过 450 毫秒没有有效扫描或轮速反馈中断时撤销驱动。两路轮速归零后点击「退出最终测试」，后端尝试恢复进入时的遥控速度设定。

仅雷达模式下，单个纸箱可用「雷达停车测距」记录发出停车指令时和停稳后的雷达读数。停稳后量车头到纸箱的实际间距，验收目标为 **20–30 cm**。记录两路轮速及间距。箱子应始终处于雷达量程内。出现多个雷达目标时，用现场实测记录间距。

用同一套 L 形遮挡、纸箱和滚动球做「只有雷达检测」和「摄像头和雷达融合检测」两组对照。两组保持小车直行，使用相同的起点和放球位置，记录首次发现、下发停车的位置，以及轮速归零时的车头余距。融合场根据连续实拍检测估计障碍移动方向。当预计障碍与小车将在前方停车区域相遇时，界面提示「监控预测目标将进入前方通道，提前停车」。

### 融合风险接口

「小车控制」内可切换两种检测方式。「只有雷达检测」用车载雷达的多目标观测生成车身坐标下的雷达热图。「摄像头和雷达融合检测」同时显示实拍画面、独立的车载雷达目标和融合热图。同一目标在融合场里只计一次。切换模式时退出当前测试档。

接通小车串口并等待两路轮速归零。在「小车起点与定位」填写雷达中心正下方的地面 X、Y 坐标（米）和车头朝向。沿用监控标定的场地原点和坐标轴，车头朝 +Y 填 0°，朝 +X 填 90°。点击「静止查看」可检查观测投影，期间方向键停用。点击「设为行驶起点」或「用此位置开始行驶定位」后，后端根据两路编码器轮速更新直行位置。等风险场显示「两路观测已对齐」，点击「启用最终测试」，待车端确认后按住 W 前进。每次手动挪车或改变朝向后重新设置起点。

轮速定位适用于固定朝向的短距离直行。两路轮速反馈中断或差异过大时，后端撤销驱动并要求重新设置起点。视觉或雷达观测失效时，后端也会撤销驱动。本机定位程序仍可向 `POST /api/vehicle/risk` 持续发送当前位姿，`camera` 和 `lidar` 可填 `null`。控制页通过以下接口显示风险场和建议动作。

| 接口 | 用途 |
| --- | --- |
| `POST /api/vehicle/risk` | 输入同一车的位姿和两路观测，返回障碍列表、稠密风险网格、通道峰值、最近前向距离、动作、原因和限速 |
| `GET /api/vehicle/frame` | 取最近一次提交的观测，并按当前时间重新检查有效性 |
| `GET /api/vehicle/config` | 读取风险计算使用的时间门限、通道宽度与建议限速 |

车路协同总览同时显示相机画面、雷达点迹、融合风险热图和小车应执行的动作。相机检测框随对应的原图一起显示，已标定的地面位置列在画面下方。雷达栏以车头为 0°，显示障碍的距离和方位。中间的风险场使用时间与坐标对齐后的目标，两路看到同一人时融合目标表只列 1 个。右侧显示巡航、减速或停车，以及速度上限和触发原因。实车执行情况需通过底盘反馈验证。

### 查看摄像头与独立视图

1. 将 `sentinel/config/devices.example.json` 复制为同目录的 `devices.json`，启用 `camera.enabled`，配置原平台的 Python 环境与检测模型。网络相机填 `rtspUrl`，USB 相机将 `deviceIndex` 设为设备编号（如 0）。重新启动后选择“摄像头感知”或“小车控制”。即使小车还没上报位姿，也可以先看实拍画面。
2. 通过“摄像头感知”“雷达探测”“风险场”进入独立视图。可以选取目标、筛选列表、看趋势与航迹、切换等高线、指向网格读取场值。实车模式的暂停按钮只冻结网页显示。安装原平台历史录制数据及关联媒体后，可通过“历史实测回放”打开原时间轴。
3. 摄像头尚未接入时，摄像头页的“本地照片 / 录像”可在浏览器中预览已有素材。VIDEO、CARLA 也支持独立预览。检测框只绘制在对应的传感器图像上。

`GET /api/vehicle/frame` 的 `capture.vision` 包含图像序号、采集时间、图像大小、像素框和 JPEG 地址。JPEG 可带 `?at=<采集时间毫秒>` 核对帧身份。位姿或雷达缺失时仍可查看新鲜的摄像头画面。配置 `camera.groundCalibration` 后，可查看当前检测框投影到地面的坐标，画面尺寸需和标定一致。该投影用于预览。相机适配器完成场地标定后，在提交的 `camera` 上填写对应的 `sequence` 和 `capturedAtMs`，并在地面目标上附同帧检测的 `trackId`。网页据此关联检测框、地面点和雷达目标。未提供这些信息时，图像仍可独立显示。雷达目标也可带传感器跟踪编号 `trackId` 以查看连续航迹。

### 用监控实拍标定地面

实时「摄像头感知」和小车融合页提供 **A · 人车**、**B · 球类**、**C · 人和球**三种显示预设。从「启动车路协同」启动时默认使用 **C · 人和球**。小车融合页用「球 1」「球 2」区分跟踪目标，可展开「自定义类别」调整小车使用的类别。

摄像头环境装好 `onnxruntime` 后，默认加载仓库中的篮球专用模型 `models/swish-ball-validation.onnx`。也可在本机 `camera.basketballOnnxPath` 指定其他支持 `basketball` 类别、固定输入尺寸且未内嵌 NMS 的 Ultralytics ONNX。设为 `false` 时用通用模型、外观补检和短时跟踪。篮球专用模型在当前画面的直接检测达到 0.50 置信度时可以参与融合停车。外观补检、跟踪补帧和低置信度专用检测仍显示为「预览」。

通过车路协同启动脚本运行，在「小车控制 → 摄像头和雷达融合检测」打开固定摄像头栏的「地面标定」。页面抓取一张当前监控画面，并叠加同帧检测框。依次点击已量过的四个地面角点，填写它们相对于同一个场地原点的 X、Y 坐标（米）。例如用 50 cm 方形地砖，可从一角开始依次填写 (0, 0)、(0.5, 0)、(0.5, 0.5)、(0, 0.5)。

点击「保存并应用标定」把参数写入本机 `camera.groundCalibration`，当前后端会立即使用这组参数。返回实时画面后，用标定范围内一个位置已知的目标核对检测框底部对应的地面坐标。摄像头换机位、角度或画幅后，重新取帧标定。

总览和风险场独立页共用固定的 0–1 色标。低值区域由淡蓝过渡到青绿，中高值逐渐过渡到黄、橙、红。风险接口还依据最近障碍距离给出停车建议。

上述结果接口在 `observations.camera` 和 `observations.lidar` 分别保留融合前的观测及其 `capturedAtMs`。空的 `observations` 数组表示这一路有效、本帧未发现目标；缺失或过期的传感器为 `null`。时间仍有效但无法和其他输入对齐时，该路观测仍可查看，`includedInFusion: false` 表示它未进入本帧风险计算。摄像头栏使用已标定的地面位置。

输入时间统一为同一时钟基准的 Unix 毫秒。每个报文描述一个位姿时刻，按位姿采样时间递增发送。相机输入已标定的场地地面坐标（米）。位姿使用同一场地原点，航向从场地 +Y 顺时针量起。雷达输入已按单个障碍聚类、换算到车身原点的距离（米）和方位角（度，向右为正）。同一行人的腿部回波应在雷达适配阶段聚为一项。雷达、摄像头在线且本帧未发现障碍时发送空数组，缺失时传 `null`。

第一阶段按 250 毫秒有效期和 100 毫秒最大时间差筛选观测，直行条件下将雷达距离补偿到位姿时刻。匹配半径是 0.15 米，同一对观测只向网格贡献一次。位姿或雷达失效时清空风险场并输出停车；相机失效时，雷达仍可触发近停，无近障时降速。车身 +X 向右、+Y 向前。近距离保护检查两路有效原始观测，避免融合后的位置掩盖较近的障碍。风险接口输出建议动作和限速。实车触发距离按延迟和制动距离测定。

## 复用与适配

| 环节 | 参赛版 | 车载版 |
| --- | --- | --- |
| 雷达输入 | TCR300 经 TCP 提供目标位置、速度 | 对接 N10P 扫描数据，标定雷达相对车体的位置和朝向 |
| 风险计算 | 按距离、闭合速度与径向近似碰撞时间计算目标强度，叠加成二维风险网格 | 先用障碍位置生成近场风险，再用连续扫描与车体运动估计补充速度和碰撞时间 |
| 显示与告警 | 浏览器显示风险网格和等高线 | 复用网页可视化，记录风险值、观测时间和数据有效状态 |
| 底盘执行 | 道路观测 | 走原厂速度控制接口，分阶段验证减速、停车和绕障 |

风险计算核心在 [risk-field.engine.ts](../sentinel/sentinel-backend/src/engines/risk-field.engine.ts)，实时数据转换和有效期处理在 [risk.ts](../sentinel/sentinel-backend/src/live/risk.ts)。车载网格范围、分辨率、数据超时和制动参数需要结合车速、探测范围、实测延迟及停车距离确定。

## 实车验证顺序

1. 用原厂工程或镭神驱动取得扫描数据，观察车体前后左右的障碍是否映射正确，验证扫描中断时的状态变化。
2. 联调近场风险值、热图和告警，记录观测时间与输出延迟。
3. 在低速下验证减速、停车及雷达掉线时的停车行为。
4. 验证候选绕障路径上整车所需的通行空间，检查绕障和不可通行时的停车行为。

烧录前需核对随车原厂工程、主控与连接方式、原厂固件恢复方法、雷达接入、编码器反馈和四驱电机控制接口。雷达软件可参考 [镭神 N10P 驱动](https://github.com/Lslidar/Lslidar_ROS1_driver/tree/M10P/N10P)，底盘软件以随车资料为准。
