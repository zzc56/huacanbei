# L150 Pro 四驱版风险场移植

电脑端第一版支持低速直行、静止障碍和一个行人的完整接近过程。固定相机的地面观测和车载雷达的障碍观测经过时间门限检查、坐标变换与一对一匹配，共用一个 SENTINEL 风险场。STM32 上传观测、执行限速和断线停车属于实车接入阶段。随车资料包括 N10P 示例，实际雷达、Wi-Fi 模块和接口以到货实物为准。

## 电脑端联调

运行车路协同平台后，在顶部选择“小车控制”。每个控制页连接独立的模拟小车，起点前方一米有一名静止行人。按住 W / ↑ 约六秒，观察摄像头先发现、雷达随后发现、融合计一人以及约 0.25 米处自动停车。按住 S / ↓ 可低速后退，松键停车；空格停车后需松开方向键再按。“重置场景”返回起点。倒车时风险场只评估车前方。实拍画面和本地素材在本页独立预览，参与风险计算的是模拟观测。

控制页通过 `/api/vehicle/drive` WebSocket 发送方向、停车和心跳。后端使用单调时钟积分，在 450 毫秒未收到新指令或心跳时停止模拟运动。页面失焦、隐藏和离开时发出停车指令。该接口仅运行模拟底盘；实体入口等待实际通信协议和编码器反馈联调。

构建后运行 `node sentinel/launch.mjs vehicle`。默认仅监听本机。网页的“离线演示”使用一个固定在场地坐标的行人，每 100 毫秒按上一帧给出的速度上限更新模拟车的位置。停在最后一帧，可重播或直接选阶段。“实车观测”读取固定摄像头画面和提交的车路观测。两种输入互相独立。

| 接口 | 用途 |
| --- | --- |
| `POST /api/vehicle/risk` | 输入同一车的位姿和两路观测，返回障碍列表、稠密风险网格、通道峰值、最近前向距离、动作、原因和限速 |
| `GET /api/vehicle/frame` | 取最近一次提交的观测，并按当前时间重新检查有效性 |
| `GET /api/vehicle/config` | 读取当前离线演示使用的时间门限、通道宽度与限速参数 |
| `GET /api/vehicle/demo/:step` | 获取离线场景指定帧，包括各阶段的首帧编号和最后一帧编号 |

车路协同总览同时显示相机画面、雷达点迹、融合风险热图和小车应执行的动作。相机检测框随对应的原图一起显示，已标定的地面位置列在画面下方。雷达栏以车头为 0°，显示障碍的距离和方位。中间的风险场使用时间与坐标对齐后的目标，两路看到同一人时融合目标表只列 1 个。右侧显示巡航、减速或停车，以及速度上限和触发原因。实车执行情况需通过底盘反馈验证。

### 查看摄像头与独立视图

1. 将 `sentinel/config/devices.example.json` 复制为同目录的 `devices.json`，启用 `camera.enabled`，配置原平台的 Python 环境与检测模型。网络相机填 `rtspUrl`，USB 相机将 `deviceIndex` 设为设备编号（如 0）。重新启动后选择“实车观测 → 摄像头感知”。即使小车还没上报位姿，也可以先看实拍画面。
2. 通过“摄像头感知”“雷达探测”“风险场”进入独立视图。可以选取目标、筛选列表、看趋势与航迹、切换等高线、指向网格读取场值。实车模式的暂停按钮只冻结网页显示。安装原平台历史录制数据及关联媒体后，可通过“历史实测回放”打开原时间轴。
3. 摄像头尚未接入时，摄像头页的“本地照片 / 录像”可在浏览器中预览已有素材。VIDEO、CARLA 也支持独立预览。预览素材独立于离线演示，检测框只绘制在对应的传感器图像上。

`GET /api/vehicle/frame` 的 `capture.vision` 包含图像序号、采集时间、图像大小、像素框和 JPEG 地址。JPEG 可带 `?at=<采集时间毫秒>` 核对帧身份。位姿或雷达缺失时仍可查看新鲜的摄像头画面。相机适配器完成场地标定后，在提交的 `camera` 上填写对应的 `sequence` 和 `capturedAtMs`，并在地面目标上附同帧检测的 `trackId`。网页据此关联检测框、地面点和雷达目标。未提供这些信息时，图像仍可独立显示。雷达目标也可带传感器跟踪编号 `trackId` 以查看连续航迹。

总览和风险场独立页共用固定的 0–1 色标。低值区域由淡蓝过渡到青绿，中高值逐渐过渡到黄、橙、红。近障停车还取决于距离，低速直行演示中距障碍约 0.25 米时就会停车，此时网格颜色可仍处在青绿色段。

上述结果接口在 `observations.camera` 和 `observations.lidar` 分别保留融合前的观测及其 `capturedAtMs`。空的 `observations` 数组表示这一路有效、本帧未发现目标；缺失或过期的传感器为 `null`。时间仍有效但无法和其他输入对齐时，该路观测仍可查看，`includedInFusion: false` 表示它未进入本帧风险计算。摄像头栏使用已标定的地面位置。

输入时间统一为同一时钟基准的 Unix 毫秒。每个报文描述一个位姿时刻，按位姿采样时间递增发送。相机输入已标定的场地地面坐标（米）。位姿使用同一场地原点，航向从场地 +Y 顺时针量起。雷达输入已按单个障碍聚类、换算到车身原点的距离（米）和方位角（度，向右为正）。同一行人的腿部回波应在雷达适配阶段聚为一项。雷达、摄像头在线且本帧未发现障碍时发送空数组，缺失时传 `null`。

在 PowerShell 中发送一帧模拟观测，小车朝场地 +X，摄像头看到车前约 0.65 米处的行人。返回的 `motion.action` 应为 `slow`。

```powershell
$stamp = [DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds()
$sample = @{
  pose = @{ xM = 1; yM = 1; headingDeg = 90; speedMps = 0.22; capturedAtMs = $stamp }
  camera = @{ capturedAtMs = $stamp; observations = @(@{ xM = 1.65; yM = 1 }) }
  lidar = @{ capturedAtMs = $stamp; observations = @() }
} | ConvertTo-Json -Depth 5 -Compress
(Invoke-RestMethod -Uri http://127.0.0.1:3001/api/vehicle/risk -Method Post -ContentType application/json -Body $sample).motion
```

第一阶段按 250 毫秒有效期和 100 毫秒最大时间差筛选观测，直行条件下将雷达距离补偿到位姿时刻。匹配半径是 0.15 米，同一对观测只向网格贡献一次。位姿或雷达失效时清空风险场并输出停车；相机失效时，雷达仍可触发近停，无近障时降速。车身 +X 向右、+Y 向前。近距离保护检查两路有效原始观测，避免融合后的位置掩盖较近的障碍。0.80 米减速、0.25 米停车及 0.22/0.10 米每秒两档限速仅用于模拟，实车参数按延迟和制动距离测定。

## 复用与适配

| 环节 | 参赛版 | 车载版 |
| --- | --- | --- |
| 雷达输入 | TCR300 经 TCP 提供目标位置、速度 | 对接 N10P 扫描数据，标定雷达相对车体的位置和朝向 |
| 风险计算 | 按距离、闭合速度与径向近似碰撞时间计算目标强度，叠加成二维风险网格 | 先用障碍位置生成近场风险，再用连续扫描与车体运动估计补充速度和碰撞时间 |
| 显示与告警 | 浏览器显示风险网格和等高线 | 复用网页可视化，记录风险值、观测时间和数据有效状态 |
| 底盘执行 | 道路观测 | 走原厂速度控制接口，分阶段验证减速、停车和绕障 |

风险计算核心在 [risk-field.engine.ts](../sentinel/sentinel-backend/src/engines/risk-field.engine.ts)，实时数据转换和有效期处理在 [risk.ts](../sentinel/sentinel-backend/src/live/risk.ts)。车载网格范围、分辨率、数据超时和制动参数需要结合车速、探测范围、实测延迟及停车距离确定。

## 实车验证顺序

1. 用原厂工程或镭神驱动取得扫描数据，观察车体前后左右的障碍是否映射正确，验证扫描中断时的状态变化。
2. 联调近场风险值、热图和告警，记录观测时间与输出延迟。
3. 在低速下验证减速、停车及雷达掉线时的停车行为。
4. 验证候选绕障路径上整车所需的通行空间，检查绕障和不可通行时的停车行为。

烧录前需核对随车原厂工程、主控与连接方式、原厂固件恢复方法、雷达接入、编码器反馈和四驱电机控制接口。雷达软件可参考 [镭神 N10P 驱动](https://github.com/Lslidar/Lslidar_ROS1_driver/tree/M10P/N10P)，底盘软件以随车资料为准。
