v0.3.6 新增摄像头车辆识别：汽车、公交车、卡车、摩托车、自行车与行人同时检测，分类计数和 CSV 保存。视觉车辆暂未与雷达车辆关联，不重复加入风险场。详见 docs/车辆识别使用说明.txt。

v0.3.5 将滚轮改为整张图像的显示缩放：X/Y 范围、刻度值和刻度数量保持原样，文字、热图、目标点和标定框一起变大。向上滚放大、向下滚缩小；超出窗口的部分可按住左键拖动查看，双击或点“恢复视图”复位。原标定、计算范围和导出数据不变。只有手动调整顶部 X/Y 输入框才会改变基础范围。

v0.3.3 新增俯视图右上角“隐藏标定框/显示标定框”按钮，隐藏不清除标定，也不改变计算或导出。雷达采集页新增“雷达参数…”：灵敏度、停止目标时间、停止线距离、水平偏移、测速范围、1～8 车道宽度及方向。先读取后设置，设置自动读回核对；操作记录在雷达保存目录的 `device-settings` 子目录。参数编码经原厂 DLL 和本地模拟雷达验证，尚未进行真实硬件写入测试。

用于连接 TCR300、保存目标数据、检测摄像头中的行人，并在“融合与风险场”页显示视频、米制目标位置和研究用相对风险场。雷达接收与 OBS 取流曾在本机验证；融合的地面坐标、时延和风险模型仍需道路标定与验证。

## 快速开始

1. 双击 `Run.cmd` 打开上位机；完整保留程序及配套 DLL。
2. 需要重新编译时，双击 `Build.cmd`。
3. 双击 `Test.cmd` 执行离线测试。请以窗口中实际输出的结果为准。
4. 无摄像头时：切换“人车视觉”→“离线示例”→“开始检测”，查看公开示例图片的识别结果。这不是道路实测。
5. 双击 `RunFusion.cmd` 直接进入“融合与风险场”。默认开启“显示标定区外车辆风险场”，有有效雷达目标时无需大区域视觉标定即可显示远处车辆场；米制行人位置仍需要地面标定。
6. 融合步骤见 [融合使用说明](docs/融合使用说明.md)，模型边界见 [融合模型与验证](docs/融合模型与验证.md)。执行 `TestFusion.cmd` 运行离线融合测试。
7. 在融合页点击 **导出研究 CSV…**，选择已经停止保存的融合实验目录，导出快照、目标和交互三张表。详见 [研究数据导出说明](docs/研究数据导出说明.md)。

## v0.3.1 优化

v0.3.2 新增大范围雷达车辆场，保留局部标定区域的行人融合；没有有效视觉输入或标定时可退回明确标记的仅雷达模式。导出新增场域类型和独立的场输出掩码。示例：近处只标定 1～9 米，80 米的有效雷达目标仍可产生热区。`FusionCoverageTests.exe` 使用合成输入验证该场景，不代表现场测量精度。

- 融合计算、预览解码和派生文件写入放到后台；界面显示计算耗时、输入丢弃和视觉合并计数。
- 视频有延迟时，从有界雷达历史中选择对应时刻的真实观测。图中注明参考时刻和场龄，当前数据断流后隐藏过期结果。
- 米制图保持 X、Y 等比例，增加速度箭头，缓存热图以减少重复绘制工作。
- 融合保存按观测和状态变化去重；稳定的空场景最多每秒保存一次状态。CSV 保留未知值、有效性、标定及来源，不把缺失数据写成 0。

新增回归与 CSV 导出检查可执行 `TestOptimization.cmd`。具体已验证的范围见 [v0.3.1 验证记录](docs/v0.3.1验证记录.md)。

运行环境为 64 位 Windows 10/11、.NET Framework 4.8。雷达界面按 x86 编译，视觉模块通过单独的 64 位进程运行；配套 Python、模型和依赖已放在 `vision`，无需单独安装 Python。项目使用软件包中的 `ProtocolsLib.dll` 进行雷达协议解析；请保留整个项目目录。

没有接设备时，可以打开界面和执行离线测试。此时不能验证实际雷达是否主动输出数据，也不能得到真实车辆目标。

## 接雷达时的操作顺序

1. 给雷达通电，通过交换机把雷达与电脑连起来。
2. 在电脑的以太网网卡上保留雷达网段地址，例如 `192.168.10.100`，子网掩码 `255.255.255.0`。若还要访问当前摄像头，可另保留 `192.168.1.100/24`；不要覆盖已有的有效设置。
3. 在原厂家上位机点击“中止”，关闭它，避免两个程序同时占用设备连接。
4. 打开本程序，核对雷达地址 `192.168.10.123`、端口 `50000`，再连接。
5. 观察连接状态、接收字节数和目标数量。没有车辆时，目标数量为零是正常情况；仅凭没有目标，不能认定网络断开。
6. 点击“开始保存”，让车辆实际经过雷达有效观察范围。
7. 点击“停止保存”，等待保存完成，再断开连接或关闭程序。“打开实验文件夹”可查看本次结果。

连接和录制是两个独立操作：连接负责接收数据；录制负责把收到的数据写入一次实验会话。保存边界以程序处理接收块的顺序为准，不回补此前处理过的数据。

v0.3.6 默认雷达保存位置是 `bin-v0.3.6/data`，视觉保存位置是 `bin-v0.3.6/data/vision`，可在界面中修改。旧版目录中的数据保持原样。界面和表格只显示近期目标，完整接收记录写入 CSV。

迁移到另一台 Windows 电脑时，复制整个项目文件夹或解压完整 ZIP，然后运行 `Run.cmd`。仅复制 EXE 会缺少依赖。`src` 内为本原型的可编辑源码，`RadarResearchHost.csproj` 可用 Visual Studio 打开；直接执行 `Build.cmd` 不需要另外安装开发工具。

连接和打开参数页不会自动发送设置命令；只有手动点击读取/设置才发出对应指令。设置前停止雷达及融合保存，调整水平偏移/测速参数组会清除当前地面标定并提示重新核对。未提供重启、恢复出厂、升级或任意原始命令发送。读回一致不代表已验证断电持久化。

## 保存了什么

每次保存生成独立的会话目录，名称包含日期、时间和唯一后缀，具体位置以界面“保存目录”和实验路径显示为准。

| 文件 | 用途 |
| --- | --- |
| `raw.bin` | 按接收顺序保存的 TCP 应用层字节，可供重新解析。它不是 ADC/IQ 原始信号，也不是包含网络包头的抓包文件。 |
| `raw-index.csv` | 记录各次接收的字节范围和主机时间，帮助查找和重放数据。 |
| `targets.csv` | 协议库解析出的目标记录，实际字段以表头为准。 |
| `events.jsonl` | 会话中记录的状态事件，每行一个 JSON 对象。 |
| `session.json` | 本次会话的元信息和时间说明。 |

**三个时间与边界约定：**

- TCP 的一次接收可能只有半个协议报文，也可能包含多个报文。接收编号和接收边界不能当作雷达帧号、帧边界。
- UTC 时间是电脑记录的接收时刻；单调时间用于衡量本机会话内的时间间隔，不受调系统时钟的跳变影响。它们都不是已验证的雷达采样时刻。
- `vendor_parse_time` 是协议库在电脑上生成的解析时间字符串，格式为 `HH:mm:ss.fff`，不是雷达硬件时间戳。目标 ID 可能复用，不能直接作为跨实验永久身份。

## 离线回放

1. 保持设备断开，点击“回放采集目录…”。
2. 选择包含 `session.json` 和 `targets.csv` 的一次会话目录。
3. 观察散点、目标表和日志；需要提前结束时点击“停止回放”。

当前界面回放流式读取 `targets.csv`，按照目标记录的主机单调时间间隔播放，不连接设备、不向雷达发送数据。`raw.bin` 保留用于后续重新解析；界面回放本身不验证原始字节是否能重新解析出相同目标。

离线测试产生的数据保存在 `test-output` 下，并在会话元信息的 `source_kind` 中标记为 `synthetic_self_test`；这些是测试输入，不能作为真实车辆采集数据。

## 视频与风险场

“人车视觉”页支持用户指定的 RTSP、本机/OBS 摄像头、离线视频和图片。可保存带框的抽样分析视频、逐帧记录和检测框。具体步骤见 [行人视觉使用说明](docs/行人视觉使用说明.md)。雷达、视觉和融合结果分别开启保存，均保留时间与来源信息。此版本没有硬件同步、一键联合录制或联合回放。

2026-10-12，用户询问商家后转述：这台 TCR300 无法检测人。行人框由视觉模型产生；雷达中的类别代码保持原始含义，不能改名为行人。v0.3 通过人工地面点标定将视觉足点映射到雷达 XY 平面，再将两种来源的目标用于相对风险场和预测接近分析。它是目标级互补融合，不是用相机识别每个雷达车辆的车型，也不是已经验证的碰撞概率模型。地面标定、时间匹配或实时来源条件不满足时，软件明确提示不可用。
