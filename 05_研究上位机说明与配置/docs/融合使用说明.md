# v0.3.5 融合使用说明

## 滚轮缩放俯视图

鼠标移到右侧图表内，滚轮向上放大、向下缩小；放大后按住左键拖动查看其他位置。双击图表或点右上角“恢复视图”回到完整范围。若系统未将滚轮送到图表，先单击图表再滚动。

v0.3.5 使用整图缩放：X/Y 范围、刻度值及刻度数量始终保持原样，字体、目标标记、热图和标定框一起变大。例如 X −20～20、Y 0～60 米不会因滚轮变成另一套刻度。超出窗口的部分拖动查看；右上角持续标出完整坐标范围。它不修改标定、风险场计算范围或保存内容。只有手动改顶部 X/Y 输入框才改变基础范围并复位视图。

## 隐藏标定框和调整雷达

- 俯视图右上角点“隐藏标定框”，可隐藏黄色虚线；再次点“显示标定框”恢复。计算、有效区域和导出仍使用原标定，不会把区外行人当作已标定。
- 雷达采集页点“雷达参数…”，选择参数组，点“读取此组”，再编辑并点“设置并读回核对”。界面会区分读回一致、读回不一致和超时。每次操作都有日志，包含修改前数值；没有自动写入和自动重试。
- 支持灵敏度、停止目标时间、停止线距离、水平偏移、最低/最高测速、车道数量及 1～8 车道的宽度和方向。车道 1～4 与 5～8 分组操作，每组独立核对，不能把部分组成功视为全部成功。
- 雷达数据或融合结果正在保存时禁止修改硬件参数，可读取当前值。先完成设置核对，再开启新一轮采集。
- 调整水平偏移/速度组会清除当前标定，请核对实际坐标后重新标定或导入。标定导出文件不会被删除。
- 图上 X/Y 是显示范围，与硬件探测能力不同；采集页和融合页分别调整。灵敏度档位的物理效果需现场核实，不能保证增大数字就能发现更远车辆。
- 设备参数接口已通过厂家 DLL 对照和本地模拟设备测试，未替用户改动真实雷达。断电保存和不同固件支持情况需现场确认。


## 小标定区与大范围车辆风险场

本版默认勾选 **显示标定区外车辆风险场**。雷达的有效车辆坐标可以在整个显示网格产生相对风险热区，例如近处只标定 10 米，仍能显示 80 米处已检测车辆的热区。顶部 X、Y 设置控制展示与计算范围，不代表雷达实际覆盖范围。

- 摄像头检测到的行人继续在视频中画框；只有脚点落在已标定区域、且时间检查通过的行人才投影到米制图并参与人车融合。
- 黄色虚线内是可进行行人融合的标定区域；区域外仅含雷达车辆影响核，不外推行人位置。
- 没有摄像头、没有标定或视频过期时，有效实时雷达目标仍可生成 **仅雷达车辆场**；界面说明未融合行人的原因。
- 人车融合可用时，远近车辆都使用与视频参考时刻匹配的历史观测；退回仅雷达模式后改用各目标最新有效接收观测，时间基准会明确记录。
- 没有有效目标、雷达断开/过期、雷达时钟异常或输入溢出时不显示有效风险场。低场值不证明没有未检出目标。
- 取消勾选可恢复只在标定区域内显示的方式。

建议远距离演示先设 X ±20 米、Y 0～100 米；按实际道路调整。新版无需通过放大或伪造标定坐标来显示远处车辆。

## 先在室内跑通界面

1. 如果使用 EasyVMS → OBS：让 EasyVMS 保持已打开且未最小化，OBS 预览能看见监控画面。
2. 在 OBS 启动虚拟摄像机，按钮应显示“停止虚拟摄像机”。此前厂家上位机的残留进程曾占用虚拟设备，请不要同时打开它。
3. 打开 `RunFusion.cmd`。在“人车视觉”选择“本机 / OBS 摄像头”，填入当前电脑经确认的 OBS 编号，再开始检测。本机此前确认 OBS 为 1；另一台电脑必须重新核对编号。
4. 在“雷达采集”连接 `192.168.10.123:50000`。雷达前方没有车辆时，没有目标是正常现象。
5. 切换“融合与风险场”。看到视频、雷达状态及标定提示，即可检查采集链路。没有标定点时可先查看雷达车辆场；检测框像素不代表行人的真实米制位置。

三页共用既有采集链路，不会为融合页再打开一遍摄像头。离线视频或图片不能与当前实时雷达混作同一场景。

OBS 桥接时，请确认 EasyVMS 正在实时预览，不能采集其录像回放窗口并当作实时画面。虚拟摄像机只能报告接收到的新帧，程序无法自动判定画面是否来自录像，也不能仅凭电脑解码时间排除网络缓存延迟。

如果暂时没有设备，可点击 **合成界面演示** 查看三者放在一起的布局；点击同一位置的 **退出合成演示** 返回采集状态。演示画面与热区是专门绘制的界面示意，不来自设备或道路实验，演示期间禁用融合保存。

## 道路部署后的地面标定

固定雷达和摄像头，让它们看见同一片近似平整地面。保持摄像头角度、焦距、OBS 裁剪和输出比例固定。

1. 在有效画面中选择分布充分、围住研究区域的至少四个地面点。不能在同一直线上，不要用悬空物体表面或人的头部。
2. 测量每个地面点在雷达坐标系中的 X、Y，单位为米。雷达字段的正负方向需现场确认；不要把屏幕左右或另一套仿真系统的坐标约定直接照搬。
3. 在融合页打开地面标定，冻结画面后点击对应像素点，输入对应的 X、Y。图片按比例显示，点击坐标会换算回原图尺寸。
4. 应用并导出标定。软件只在标定点围成的有效区域内投影行人框的底部中心。
5. 用未参加求解的额外地面检查点验证位置误差。四点拟合误差很小不证明真实定位准确；镜头畸变、脚被遮挡、坡度、检测框偏移都会影响位置。

重新开设备会话需要重新确认/应用标定。分辨率变化会失效。摄像头转动、OBS 切换场景或裁剪即使输出尺寸相同，也应主动清除并重新标定；软件不能自动识别所有同尺寸画面变化。

平面映射的理论条件见 [OpenCV 单应变换说明](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)。本程序没有自动测量地形或自动完成镜头畸变校正。

## 时间对齐

摄像头采用电脑取得/解码画面的时间，雷达采用电脑接收数据的时间。画面上摄像头自带的日期文字不参与匹配。这些时间不是曝光和雷达采样的硬件时间戳。

界面提供摄像头时间偏移和匹配容差。偏移的符号与当前参数解释以界面和保存元信息为准；调整后需用同时可见的运动事件检验。容差放大只能让更多数据进入匹配，不能消除延迟。OBS、网络、解码和推理延迟可能随时间变化。

当前定义为 `用于对齐的视觉时刻 = 电脑取得画面的 UTC + 摄像头时间偏移`，正值后移、负值前移。默认偏移 0 ms、匹配容差 500 ms、观测有效期 1500 ms。默认值用于调试，不是已经测得的相机时延。

v0.3.1 会在每个雷达目标的短时历史中，选择最接近视觉参考时刻、且满足容差的真实观测，再按模型作短时位置推算。历史最长 20 秒，每个目标最多 512 条、全部目标最多 32768 条。容量上限不保证每个高频目标都能保留完整 20 秒；没有足够历史时明确显示匹配不可用。

例如经实验测得视频约延迟 1 秒，可试设偏移为 `-1000 ms` 并验证对齐。此时图中的风险场描述过去的视频时刻；**不能把它当成当前时刻的道路状态**。参考场龄和有效期会显示在界面，保存中也保留 `observation_utc`、`reference_lag_ms`、`valid_until_utc` 和 `alignment_version`。当前两路数据仍需持续更新，旧历史不能代替当前的有效连接。

数据断流、过期或超出容差时，不把旧热力图继续当作实时结果；“不可用”也不等于道路安全。

## 保存研究数据

- **雷达采集 → 开始保存**：原始 TCP 字节、接收索引、目标 CSV。
- **人车视觉 → 保存采样与结果**：带框的抽样分析视频、帧时间和检测框。它不是全帧率原始监控录像。
- **融合页 → 保存融合结果**：后台保存派生目标、时间匹配/有效性、相对风险场及模型、标定元信息。

三种保存分别开启和停止。需要完整原始视频时，同时使用摄像头/EasyVMS 的原始录像功能。OBS“启动虚拟摄像机”只是提供图像输入，不会自动保存录像。

融合默认保存在 `bin-v0.3.1/data/fusion/fusion_日期_时间_随机后缀/`。`fusion.jsonl` 每行是一次后台派生快照；观测和状态不变时去重，稳定的空场景最多每秒保存一次状态，开始/停止和状态变化可额外留记录。仍可能连续两行使用同一个视觉帧，不能把文件行数当成独立相机帧数。`fusion-session.json` 保存会话元信息和结束状态；`finalized=false` 表示没有正常完成收尾，需检查文件。

快照保留原始视觉帧序号和时间、雷达目标/接收块序号、原观测时间、对齐时刻、标定和模型版本。网格按 Y 行、X 列展开：`index = y_index * grid_width + x_index`。不可用的场为 `null`。`valid_field_mask` 表示有模型场输出的网格，`calibrated_area_mask` 表示参与视觉融合的区域；前者为真而后者为假的位置只有雷达影响核。场输出范围不等于传感器完整探测范围。

`field_scope` 分别取 `calibrated_joint`（标定区联合场）、`radar_wide_joint_local`（大范围雷达与局部联合场）、`radar_only`（仅雷达场）或 `unavailable`。仅雷达模式下 `time_matched=false`，不能解读为已与视频同步。不同场域的峰值/均值应按模式和网格范围分别分析。

停止融合保存后，点击 **导出研究 CSV…** 并选择该次实验目录。导出在后台进行，新建独立导出目录，包含 `frames.csv`、`objects.csv`、`interactions.csv` 和 `manifest.json`。网格仍在原始 JSONL 中。导出说明见 [研究数据导出说明](研究数据导出说明.md)。

## 性能和异常状态

融合工作线程负责计算、图像解码和派生文件写入，界面约每 250 ms 取最新结果。视觉输入拥堵时合并到最新帧，雷达输入按顺序保留在容量为 4096 的队列中；累计合并和丢弃数显示在页面。雷达队列溢出时，在受影响的历史窗口内停用联合场。这里的队列计数不代表原始雷达保存发生丢包；是否完整采集仍需检查原始会话和设备链路。

关闭窗口会等待后台收尾；如果写入未结束或失败，会保留窗口并显示提示。请检查磁盘空间和会话结束状态后再尝试关闭，不要在写入中直接结束进程。

如果融合计算在保存期间失败，会停止本次融合保存并把 `fusion-session.json` 标成 `finalized=false`、`error_code=processing_failure`。已经写好的记录仍保留，但不能当作完整实验。雷达和视觉的独立保存状态请分别查看对应页面。

米制图 X、Y 的一米使用相同像素长度，因此宽高比例会随研究范围变化。青色方块是雷达目标，黄色圆点是视觉行人；箭头表示速度方向与 0.5 秒位移，绘图长度上限为 4 米，速度未知时不画箭头。

## 可以从本版结果得出什么

可以检查目标级融合链路、研究风险热区、导出带来源和时间的派生数据。风险数值是模型相对指标，颜色不是经过统计校准的事故概率；雷达目标的具体车型、质量、尺寸没有从当前数据中可靠获得。

用户当前在室内，因此此版本的软件测试不能代替道路上的空间误差、漏检率、轨迹准确度、时延漂移和冲突预测验证。进入正式实验前记录独立位置与冲突真值，再比较模型结果。
