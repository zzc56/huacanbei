# 雷达、行人检测与风险场：模型及验证边界

## 数据怎样进入同一个地面坐标系

雷达目标使用厂家字段 X、Y，界面按“横向 X、纵向 Y”的约定显示；物理轴的正方向仍需现场验证。摄像头检测框使用原始图像像素，不使用缩小后的预览图坐标。行人框底边中点作为候选脚点，经过地面单应变换投影到雷达坐标系。

标定点应来自固定安装、近似平面的道路，并覆盖实际分析区域。至少需要四组不共线的像素点与地面实测点；点集中在一条线或很小区域时，标定不可靠。只在标定点凸包内使用映射，不对远处、坡道或凸包外区域盲目外推。

脚点是假设，不是直接测量的地面位置。脚被车遮住、检测框截断、阴影误检和摄像头抖动，都可能使投影错误。重投影误差低只说明选取的标定点拟合较好，不能证明所有检测框的位置准确。

摄像头来源重新启动、分辨率变化或设备连接会话变化后，应重新核对标定并显式应用。摄像头或雷达的位置、朝向变化后，即使图像尺寸未变，也必须重新标定。

## 时间与来源门控

两路融合使用主机记录的 UTC 时间，并允许显式设置摄像头时间偏移。Python 的单调纳秒只用于该摄像头运行周期内的运动估计，不直接与 C# 的 Stopwatch 计数比较。

主机接收、图像解码时间包含各自延迟，不等于硬件曝光或采样时间。手工设置偏移能帮助对齐，但不能据此声称硬件同步。要在道路上测量误差，并保存偏移、容许时间窗及标定版本。

来源门控依据输入类型和当前会话，不会自动识别视频内容的实际来源。用 OBS 虚拟摄像机桥接时，应确认 EasyVMS 窗口处于实时预览；如果窗口正在回放录像，本程序仍可能看到“本地摄像头”输入类型。解码时刻新鲜也不能排除源视频缓冲已延迟，需要实测端到端延迟。

只有来源有效、标定有效、两路新鲜且时间差在允许窗口内，才输出人车融合场。离线文件、单张图片与当前实测雷达不能自动当作同时发生的同一场景。v0.3.2 启用扩大雷达场域后，视觉或标定不可用时可退回明确标记的仅雷达车辆场：仅使用有效实时雷达目标，不加入行人或交互贡献。雷达数据缺失、过期或时钟异常时仍不可用，不用全零数组表示“没有风险”。

v0.3.1 的对齐版本为 `host-utc-nearest-history-v2`：保持当前两路新鲜度门控，同时按修正后的视觉时刻，从有界雷达历史中逐目标选择最近的真实观测。目标时间差和有效期相对于该参考时刻检查；最近一条接收心跳不能代替不存在的历史目标。负偏移产生的场描述过去时刻，记录中明确保存参考时刻、场龄和有效期，不能自动解释为当前道路状态。风险公式版本仍为 `roadside-relative-risk-v1`。

有效观察窗口内两路都没有有效目标时，标记“空观测不能证明安全”，风险场保持不可用，不输出表示安全的全零场。这个状态应与断流区分，也不对遮挡、漏检或观察范围外对象提供安全保证。

## 行人速度与交互量

行人速度由连续、可关联的地面位置和该摄像头单调时间差估计。首个观测点、来源重启、长时间断档、异常位移或无法可靠关联时，速度应保持未知。不得把重新出现的人与过期轨迹硬连，制造一个很大的速度。

目标间最近接近时间、最近距离和接近速度建立在短期匀速假设上。它们帮助比较交互强弱，不能直接替代真实碰撞概率、人的意图或车辆制动能力。

## 旧风险模型能复用什么

只读检查了 `E:\car\risk-field-independent-platform\risk_core.py` 及 `independent_app\risk_api.py`。

| 可复用的部分 | 实测接入前需要处理的条件 |
| --- | --- |
| 独立于 CARLA 的固定状态计算、网格生成 | 每次计算只使用当前有效观测，防止累积旧目标。 |
| 目标轮廓外距离衰减、速度方向增强、叠加场 | 参数是模型假设，应版本化并通过实测对照验证。 |
| 有限数、非负参数和网格大小检查 | 同样检查实时输入与输出，异常时停止输出。 |
| 原始场与显示场分开保存 | 保留原始量，明确显示变换，避免把颜色强弱当概率。 |

**不能原样套入的内容：**

- 旧模型坐标是自车局部 X 向前、Y 横向；当前雷达是 X 横向、Y 纵向。必须做明确坐标变换，不能只改图上的轴名。
- 旧模型需要 yaw、加速度、尺寸、质量和目标类别。当前硬件未完整观测这些量；不能随机猜质量、车型或加速度来冒充实测。若采用固定尺寸或其他先验，必须明示并保存参数。
- 旧道路边界场以自车为中心，使用给定车道数和宽度。路侧雷达坐标的原点不是行驶车辆，也没有自动获得真实道路边界。
- 旧模型采用每帧第 1/99 分位归一化。同一个颜色值在不同帧可对应不同原始量，不能直接用于跨时间阈值、跨实验排序或概率解释。比较实验时应使用原始场或固定显示尺度。
- 仿真中的行人、车辆轨迹和连续净距证书使用已知运动状态。实测有漏检、身份交换和测量误差，不能沿用仿真真值保证。

当前融合指标必须有独立模型版本与参数说明。界面上的风险值是相对交互指标，不是碰撞概率，也不是经过验证的事故预测结论。

## 当前融合模型的公式与默认参数

当前模型版本为 `roadside-relative-risk-v2-coverage`。方向性核公式沿用 v1，本次版本化变更是雷达场域扩大、行人/交互贡献的区域限制和仅雷达回退语义。它没有原样复刻依赖质量、加速度和自车道路边界的旧公式。

每个对象先按速度方向建立沿向和横向轴。从网格点到对象中心的距离分别为 `d沿`、`d横`，扣除半个假设轮廓尺寸后得到：

```text
q沿 = max(|d沿| − length/2, 0)
q横 = max(|d横| − width/2, 0)
空间核 = 1 / (1 + 0.20 × q沿² + 0.50 × q横²)
速度增益 = exp(min(0.16 × speed × 前向方向系数, ln(6)))
对象贡献 = weight × 空间核 × 速度增益
```

前向方向系数为速度方向与“对象到网格点”的单位向量点积，并截断到非负。未知速度不提供速度增益，未知或近静止对象的空间核暂采用 +Y 方向先验；对象轮廓和方向假设不等于实测几何形状。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 雷达目标轮廓 | 4.5 × 1.8 米 | 可配置先验，不是由雷达测出的车长车宽。 |
| 行人轮廓 | 0.6 × 0.6 米 | 可配置先验。 |
| 雷达目标权重 | 1.0 | 相对模型权重，不是概率。 |
| 行人权重 | 1.2 × 检测置信度 | 置信度参与贡献权重，不等于位置误差或碰撞概率。 |
| 交互权重 | 2.0 | 附加接近区域的贡献。 |
| 预测时域 | 3 秒 | 短期匀速假设。 |
| 交互距离尺度 | 2 米 | 最近距离的衰减尺度。 |
| 速度增益上限 | 6 | 防止指数无界增长。 |
| 行人速度上限 | 4 米/秒 | 关联合理性门控，可配置。 |
| 默认来源新鲜度 | 1500 毫秒 | 过期观测不继续计算。 |
| 默认时间匹配窗 | 500 毫秒 | 主机接收时间近似容差，不能证明硬件同步。 |

对于有可靠速度、正在接近且最近接近时刻处于预测时域内的雷达—行人对，设相对位置为 `r`、相对速度为 `v`：

```text
t最近 = −(r·v) / (v·v)
d最近 = |r + v × t最近|
交互强度 = exp(−d最近² / (2 × 距离尺度²))
          × (1 − t最近/预测时域) / (1 + t最近)
```

在两者预测最近位置的中点添加一个小范围空间核，权重为交互权重乘交互强度。它是一个模型化的近距与时间增强项；未知行人速度、正在远离或超出时域的对象对不会据此生成预测交互。

原始场是对象贡献与交互贡献之和。显示采用固定变换 `显示场 = 原始场 / (1 + 原始场)`，用于压缩色彩范围。显示值即使处于 0～1，也不是碰撞概率；比较实验应同时保留原始场、模型版本和参数。

## 有效区域、导出与计算限额

网格中的每个点都检查地面标定有效区域，保存为 `calibrated_area_mask`。v0.3.2 扩大模式下，雷达车辆核可以覆盖整个显示网格；行人及交互核仍限制在标定区内。`valid_field_mask` 表示当前模型场输出范围，其外原始场、显示场导出为 `null`。最大值和均值只统计这个输出范围，并需结合 `field_scope` 解释。仅雷达模式的 `calibrated_area_mask` 全为假，不声称有视觉融合。模型在某网格输出数值不等于该位置获得传感器完整覆盖；小数值不证明无风险。关闭扩大模式时，恢复原来的凸包外未知值语义。

融合导出为 `fusion.jsonl` 与 `fusion-session.json`。逐条记录包括模型版本及公式指纹、参数、标定、两路运行会话、源观测序号、主机时间、来源质量、目标和风险场。未知行人速度和未确认的雷达置信度保存为 `null`。过期或其他门控失败时，整个场及统计值保存为 `null`。

融合结果是派生数据。原始雷达 TCP 和摄像头分析视频仍需在各自采集页单独开始保存，融合保存不会自动替代两路原始记录。

为限制计算与缓存，当前支持最多 128 个雷达目标、128 个行人，默认雷达上限 128、行人上限 64；有效预测交互默认只保留强度最高 32 项，截断会记录质量提示。网格最多 50000 点，同时限制“网格点数 × 配置的对象及交互上限”不超过 500 万。相同输入的场可复用缓存。这些限额防止配置无界增长，不代表在任何电脑上都能达到指定刷新频率。

## 离线验证

`tests/FusionTests.cs` 使用明确标记的人工数据检查以下行为：

1. 单应变换、反投影及序列化一致性；退化标定拒绝，凸包外不投影。
2. 会话重启与分辨率变化后的标定失效。
3. 两路新鲜度、时间差、来源和离线混用门控。
4. 行人速度不会跨断档、重启或不合理跳变估计。
5. 有效域内风险有限、非负，域外保持未知；无有效数据时不输出零风险场。
6. 最近接近时间与速度的已知手算结果、逐目标时间门控、异常 UTC、快照隔离及计算限额。
7. 导出文件的正常结束标记、缓冲尾部、来源追溯、模型指纹与缺失值语义。

具体通过项以测试报告为准。人工数据测试证明的是计算和门控逻辑，不能证明真实摄像头检测、雷达分类或风险预测性能。

2026-10-12 对当前构建执行了 14 组离线融合测试：1283 条检查通过、0 组失败。报告位于 `test-output/fusion-20261012T135915330/test-report.json`，明确标记人工输入、未使用网络及未测试硬件。

## 道路验证的最小闭环

1. 固定两台设备，测量覆盖区域内的地面点，保留原图、点位表和标定参数。
2. 用未参与拟合的检查点报告位置误差，按远近和横向位置分组，不只报告拟合误差。
3. 对同一批过车、行人片段人工标注，测量两路时间偏移、错配率、行人速度误差和断档后的恢复行为。
4. 保存缺失、遮挡、离线/实测来源与异常记录，检查失效时界面是否清楚显示不可用。
5. 风险场与人工确认的接近事件、常用冲突指标或独立轨迹真值对照；按采集时段划分训练/调参与测试，避免同一段数据同时调参和验证。

在完成这些步骤前，展示热力图可以用来检查实现，不能作为“更准确”或“更安全”的证据。
