# 人车视觉 v0.3.6

## 没接摄像头也可以试

1. 双击项目根目录的 `Run.cmd`。
2. 切换“人车视觉”，点击“离线示例”，再点击“开始检测”。
3. 示例图来自 OpenCV，包含两个人；检测完成后保留带框的图片。“检测：未运行”表示这张图片已处理完成。

示例只验证软件能推理、显示，不能用于说明道路检测准确率。

## 接实际摄像头

### 直接 RTSP 输入

1. 保持摄像头供电，摄像头、交换机和电脑网络互通。
2. “画面来源”选择“网络摄像头（RTSP）”。
3. 在旁边输入摄像头厂商提供的完整取流地址；设备账号和密码只在本机输入框填写。网页地址 `http://192.168.1.11` 不是 RTSP 地址。EasySVMS 已能预览，也不代表本程序已接入视频。
4. 点击“开始检测”。有画面后，在镜头可见范围内走动，观察行人框。

本程序不记住 RTSP 地址和密码，不尝试默认密码，也不会把画面上传到云端识别。当前设备的具体 RTSP 路径与实时兼容性，以实测为准。

### OBS 虚拟摄像机输入

若暂时没有 RTSP 地址，可继续使用之前的 OBS：

1. OBS 添加“窗口采集”，选实际显示摄像头画面的 EasySVMS 窗口。
2. 确认 OBS 预览完整且没有被遮挡/最小化造成停帧，再点击“启动虚拟摄像机”。
3. 本程序选择“本机 / OBS 摄像头”，输入相应设备编号，点击“开始检测”。编号取决于本机枚举顺序，0 不一定是 OBS，也可能是电脑自带摄像头。

本程序只在点击开始后打开指定来源。停止检测会释放输入。OBS 窗口采集含屏幕缩放和显示延迟，不等于摄像头原始码流。

本机已验证 OBS Virtual Camera 编号为 **1**（编号 0 是内置摄像头），并于 2026-10-12 读到实际监控画面。换电脑后编号需要重新确认。**先启动 OBS 虚拟摄像机，再启动上位机检测；重启 OBS 虚拟摄像机前，先释放所有上位机的视频输入。** 本次曾遇到旧厂家程序退出界面后仍在后台持有视频连接，导致 OBS 启动失败，详见 [排查记录](OBS启动失败排查_2026-10-12.md)。

## 保存视频和检测结果

1. 先“开始检测”，看到连续画面。
2. 点击“保存采样与结果”，确认下方变为“保存：进行中”。
3. 结束时点击“停止保存”，再“打开文件夹”。

| 文件 | 内容 |
| --- | --- |
| `video.mkv` | 保持输入尺寸的带框抽样分析视频，无音频，FFV1 编码。 |
| `frames.csv` | 每个被处理并保存的帧，包括没有检测框的帧；含时间、尺寸、推理耗时、人数、车辆数和总检测数。 |
| `detections.csv` | 人车类别、检测框左上角 x/y、宽/高、置信度，全部为原输入画面的像素坐标。 |
| `session.json` | 来源类型、模型哈希、阈值、采样上限、结束状态和时间定义。 |

默认采样上限 5 帧/秒，是处理上限；电脑性能、视频尺寸和源速率会影响实际帧率。队列只保留最新帧，未处理的帧不会进入分析录像。文件视频按原播放时间推进，可能跳过处理不及的帧；它不是逐帧全量离线分析工具。

录像用实际时间间隔安排帧时间，避免把抽帧录像加速播放。FFV1 文件可能较大，需要播放软件支持该编码；后续研究若需要完整帧率的原始视频，请同时使用 EasySVMS 或摄像头自身的录像功能。

**单张图片处理后立即结束，保存按钮用于连续视频输入。** 原始图片可自行保留，图片识别结果可从预览查看。

## 时间与研究边界

- `captured_utc`：电脑收到/解码该帧时的 UTC 时间；不是摄像头曝光时刻，也不是图像上显示的摄像头时钟。
- `monotonic_ns`：本机单调时钟，纳秒单位；和雷达文件的 `Stopwatch` 原始 tick 单位不同，不能直接相减。
- `source_time_ms`：离线视频自带的呈现时间；实时 RTSP/摄像头暂不提供这个字段。
- `video_pts_ms`：当前分析录像的相对播放时间，从零开始。
- 没有持续的行人跟踪 ID，不估计米制位置或速度，没有雷视时间同步、空间标定和目标关联。

摄像头时间与电脑时间不一致，需要在摄像头设置里校时。即使时间显示一致，网络传输和解码延迟仍然存在。构建风险场前需要单独验证时间对齐、标定与检测误差。

## 迁移

完整复制项目或解压当前版本 ZIP，保留 `bin-v0.3.6`、`vision`、`Config`、`lib`、`tests/assets` 等目录，双击 `Run.cmd`。无需复制旧采集数据。`PrepareVision.py` 仅用于开发者重建运行环境，普通使用不必执行。

## 车辆识别

v0.3.6 人车视觉

新增摄像头六类检测：person 行人、car 汽车、bus 公交车/客车、truck 卡车、motorcycle 摩托车、bicycle 自行车。
操作：进入“人车视觉”页，选择原来的本机/OBS 或 RTSP 来源，点击“开始检测”。车辆默认启用，无需额外模型。
绿框为行人，蓝色框为车辆；标签使用英文类别与模型分数。界面显示每类当前帧数量，不是去重交通流量。
点击“保存采样与结果”可保存带人车框的抽样 video.mkv，以及 frames.csv、detections.csv、session.json。
视觉 session schema_version=2；frames.csv 保留 person_count，新增 vehicle_count（含自行车/摩托车）和 detection_count。
detections.csv 的 class/label 分别保存 COCO 类号与类别名称，不再固定写成行人。
跨进程 boxes 新增 class_id/label；旧版缺少类别的框仍按行人解释。合并队列和融合引擎保留类别。

融合边界：摄像头车辆显示在视频并保存在视觉结果中。当前没有相机车辆与雷达目标的一对一关联，故视觉车辆不作为额外目标加入风险场，避免重复计数；雷达车辆风险场正常显示，视觉行人仍只在有效地面标定区投影。
检测框不是车牌识别、车型精细分类或可靠轨迹 ID。类别/置信度需用现场标注验证；远处小目标、遮挡、低光可能漏检。

验证：含六类重叠框与类内去重、类别/数量 CSV、C# JSON 类别校验、后台复制与行人融合隔离检查。离线道路照片检出两辆汽车；这不能代替实时现场精度验收。
