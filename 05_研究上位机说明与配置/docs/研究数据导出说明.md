# 融合会话导出为研究 CSV

## 怎么用

先停止融合保存，再选择包含 `fusion.jsonl` 和 `fusion-session.json` 的实验文件夹。原始文件保持不变，每次导出创建一个新的独立目录。

在上位机中：**融合与风险场 → 导出研究 CSV… → 选择本次实验文件夹**。导出期间可以继续查看采集界面，完成后会提示输出目录。

命令行方式（在项目文件夹内）：

```powershell
& '.\vision\runtime\python.exe' -X utf8 -u '.\ExportFusion.py' --session 'E:\实验数据\fusion_会话目录'
```

指定导出位置：

```powershell
& '.\vision\runtime\python.exe' -X utf8 -u '.\ExportFusion.py' --session 'E:\实验数据\fusion_会话目录' --output-root 'E:\研究CSV'
```

工具只依赖 Python 标准库。默认导出到源会话同级的 `exports` 文件夹，目录名含 UTC 时间和唯一后缀，不覆盖以前的结果。正常结束返回退出码 0；失败返回 2。标准输出是一条 JSON，包含 `success`、安全提示和 `output_directory`，供上位机调用。

## 得到哪些文件

| 文件 | 内容 |
| --- | --- |
| `frames.csv` | 每条融合快照的时间、原视频序号、来源会话、质量、对齐状态和风险统计。 |
| `objects.csv` | 每条快照中的雷达目标与行人，包括坐标、速度、是否已知速度、原始时间和来源事件序号。 |
| `interactions.csv` | 最近接近时间、最近距离、接近速度和相对交互指标。 |
| `provenance.jsonl` | 按哈希引用的配置与标定版本，保存必要的白名单字段。 |
| `manifest.json` | 导出是否完成、计数、源文件 SHA-256、模型版本、来源是否正常结束及限制说明。 |

默认不生成逐网格 CSV，以免一次实验产生大量重复网格行。`frames.csv` 保留有效、未知网格数；逐格掩码与原始场仍在源 `fusion.jsonl` 中。

CSV 使用带 BOM 的 UTF-8，便于 Excel 打开中文。含逗号、双引号或换行的文本按标准 CSV 引号规则保存。

## 时间、重复帧与未知值

v0.3.2 新增 `field_scope`，用于区分 `radar_only`（仅雷达）、`radar_wide_joint_local`（全范围车辆场与局部人车融合）、`calibrated_joint`（仅标定区联合场）和 `unavailable`。仅雷达模式无需视觉标定，且 `time_matched=false`；不能把它当成人车融合结果。

`valid_field_cells` 统计模型有输出的网格，`calibrated_cells` 统计允许视觉融合的网格，`radar_only_cells` 统计有场输出但无视觉融合的网格；`unknown_cells` 统计不支持场输出的网格。逐格对应关系在源文件的 `valid_field_mask` 和 `calibrated_area_mask` 中。旧版没有前一个掩码时，按旧版标定域解释。模型场输出范围不代表雷达完整探测范围。配置记录保留 `ExtendRadarField`，不同场域的峰值和均值不可直接混为同一研究条件。

- `snapshot_index` 是导出时按原 JSONL 顺序分配的记录号，`source_line` 是原文件行号；它们不是雷达硬件帧号。
- 重复的 `vision_sequence` 保留，不去重。同一个视频帧可能被多个融合快照引用。
- 不按时间重新排序；即使时钟异常导致原行的时间倒退，也保留原顺序及质量信息。
- `host_utc` 是生成快照的主机时间。`observation_utc` 是该场所描述的参考观测时刻，可能早于生成时刻。
- `alignment_version`、`historical_alignment`、`reference_lag_ms`、`valid_until_utc` 与 `radar_history_samples` 保留历史对齐的信息。历史场不能直接解释为当前道路状态。
- `source_sequence` 和 `receive_chunk_sequence` 保留原目标事件与接收块的来源，不能直接当作硬件帧号。
- 空白单元格代表 `null` 或未知，不替换为 0。数值为 0 的已知速度等仍保存为数值 0。
- `velocity_known=false` 时速度列为空。`field_available=false` 时风险最大值与均值为空，不写成“零风险”。

风险值是相对研究指标，不是碰撞概率。空观测或未检出行人不能证明安全。

## 来源与可复查性

`manifest.json` 的 `source_jsonl_sha256` 对正常完整读取的源字节计算，`source_metadata_sha256` 对源元信息字节计算。导出成功才提供完整源 JSONL 哈希。失败时最多提供已读前缀的哈希，不冒充完整文件哈希。

`config_ref`、`calibration_ref` 对原始配置或标定的规范化 JSON 计算 SHA-256，对应 `provenance.jsonl` 的 `reference_sha256`。保存的 `value` 是白名单与脱敏后的内容，另有 `value_sha256`；它不一定与原始引用哈希相同。完整原始记录可依据源文件哈希回查。

`manifest.json` 的 `export_completed` 与兼容字段 `completed` 含义一致。它们为 `true` 只表示这次转换完成。`source_finalized=false` 表示原采集会话未正常结束；工具可转换已有完整行，但会保留明确警告，不能据此认为实验完整。

## 失败、取消与安全限制

损坏的 JSON、截断尾行、无效字段、重复 JSON 键或非有限数字会使导出失败。已正常结束的源会话若实际行数与元信息不符，也会失败，避免完整行边界截断被误当完整实验。不会跳过坏行继续宣称成功。已生成的 CSV 可能只含前面的有效记录；`manifest.json` 保持未完成并记录错误代码和行号。

正在保存的源文件若在导出期间改变，会返回 `source_changed`。建议先停止保存；用户取消或进程被强制结束后，也应把未完成目录视为部分结果。

输入按行读取，不一次载入整个实验。默认限制单行 8 MiB、源 JSONL 总量 4 GiB、元信息 1 MiB、网格 50000 点、JSON 嵌套 32 层，以及配置/标定版本数量。超限会明确失败，可按采集会话分段导出。

导出不连接设备、不加载任何 URL。只复制必要字段；URL 和凭据模式从文本中移除。可能被表格软件解释为公式的文本会加一个前置单引号，负数速度等数值不受影响。涉及这种特殊标识时，按源 JSONL 核对，不能把公式转义字符当作原始身份的一部分。
