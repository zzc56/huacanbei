# 离线验证与现场验收

本文件列出第一版的重要验证项。它是验收标准，不表示每一项已经执行或通过。自动化用例的实际覆盖范围以 `Test.cmd` 的输出和测试代码为准。

## 离线测试

| 项目 | 检查方法 | 通过条件 |
| --- | --- | --- |
| 构建与依赖 | 执行 `Build.cmd`，再启动 `Run.cmd`。 | x86 程序启动，协议 DLL 可以加载；不依赖原厂家上位机同时运行。 |
| 分片与粘包 | 把明确的协议测试数据分成不同大小的块，再合并多报文输入。 | 解析结果与完整输入一致，不把 TCP 接收块当帧。 |
| 本地 TCP 链路 | 由本地回环测试端发送标明来源的合成输入。 | 接收、解析和保存链路可贯通；不需要连接真实雷达。 |
| 原始数据可重建 | 对比全部索引的字节偏移、长度与 `raw.bin`。 | 偏移连续且无重叠，长度之和等于原始文件长度，可按索引还原录制期间接收的字节。 |
| 时间记录 | 检查 UTC 格式、单调计数及相关元信息。 | 时间格式明确，同一会话单调时间不倒退，没有将主机接收时刻标成设备采样时刻。 |
| 开始、停止保存 | 连接期间多次开始和停止，停止后继续提供输入。 | 每次产生独立会话，停止后文件不再增长，已有缓冲被刷新。 |
| 空目标 | 输入没有目标事件的数据，或保持连接空闲。 | 目标为零不会被宣称为“雷达故障”；接收、连接、目标状态含义分开。 |
| 异常处理 | 使用本地测试夹具造成连接结束或写入错误。 | 异常可见，不继续显示“保存成功”，停止流程不使程序永久卡住。 |
| 界面离线回放 | 流式读取已知会话的 `targets.csv` 并按主机单调时间间隔播放。 | 目标字段可复查，模式明确，回放不向设备发送数据。 |
| 原始数据重新解析 | 测试夹具把已保存 `raw.bin` 按索引重新送入协议库。 | 已知输入的目标内容一致；此项与界面 CSV 回放分别验证。 |

有些协议字段只能使用真实设备样本验证。人工构造测试输入即使可被 DLL 解析，也不能证明与当前雷达固件完全兼容。合成数据仅用于软件自测，不能用于报告真实车辆检测性能。

## 首次接设备：短采集

建议先做 30～60 秒短采集，确认基本闭环后再进行长时间实验。

1. 先在厂家上位机确认雷达能够正常显示真实车辆目标，再中止并关闭厂家程序。
2. 用自研上位机连接同一设备，记录连接状态和收到的数据量。
3. 在有车辆经过时，查看散点图、目标表是否持续更新。不要通过同时连接两个软件进行比较，以免影响设备连接。
4. 点击“开始保存”，观察保存状态。
5. 点击“停止保存”，确认文件关闭、原始字节与索引一致，目标记录能够读出。
6. 检查回放结果与本次实际观察是否相符，并记录设备型号、固件、安装方向、采集场景。

如果 TCP 连接建立但始终没有收到字节，先确认设备是否会主动输出、是否存在连接数限制、是否需要启动输出命令。不要猜测并发送配置指令。

## 第二轮：持续采集与故障恢复

在短采集成功后，按正式实验时长做持续运行。检查内存是否持续增长、界面是否卡顿、数据是否间断，以及文件大小和行数是否一致。再执行一次拔网线、恢复连接的受控测试，检查错误提示、会话结束行为与重新连接步骤。

当前版本按顺序接收、解析和写文件。磁盘写入较慢时会延后后续处理；离线测试不能证明长期采集的实时性能。首次道路验证请使用本地磁盘并观察接收是否持续更新。

停止保存、断开连接、关闭窗口三种操作都需要检验，避免只测试正常的一条操作路径。

## 当前仍待验证

- 真实 TCR300 固件输出和现有协议库的适配情况。
- 目标字段的单位、轴方向、默认值与分类含义。
- 是否可从设备报文得到完整目标周期、设备帧号及可靠设备时间。
- 长时间采集稳定性，以及断线与写入失败时的数据完整性。
- 摄像头原生取流、录像和雷视同步。

采集程序本身通过验证，不代表雷达测量精度或风险场模型已通过验证。正式研究还需要标定、误差分析、对照数据与算法评估。
