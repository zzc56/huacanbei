# v0.3.3 TCR300-Self 参数接口核对

依据本地原厂 v2.0.7 的 `audit/app-receive-il.txt`、`audit/protocol-il.txt` 及中文语言资源；没有对真实设备发命令。

外层发送 ID 为 `0x0500 + (radarId << 4)`，调用原厂 `Pro_Mainland_COM.PackageFrameByteList`；读取回复为 `0x0501`，payload[0] 为 readCode|0x80。原厂的 0x0502 ACK 不足以证明参数生效，本版最终通过明确读取相同参数核对。报文无事务编号；本版单次串行操作，必须在同一连接、同一雷达编号上收到相应组回复。

| 参数组 | 读取 / 设置 | payload 编码 |
|---|---|---|
| 灵敏度 | 16 / 96 | 设置 b1=1，b2=档位 0～10；读取 b2 |
| 停止目标时间 | 20 / A0 | b1，整数秒 0～255 |
| 停止线距离 | 19 / 99 | b1,b2，大端无符号整数/100，最大655.35m |
| 水平偏移 / 最低测速 / 最高测速 | 1A / 9A | b1～6，三个大端有符号16位数/100 |
| 车道数量与1～4车道 | 1B / 9B | b1数量，b2～5宽度×10，b6四组两位方向码 |
| 5～8车道 | 1C / 9C | b1～4宽度×10，b5四组两位方向码 |

表内命令为十六进制。参数下标从 payload 的命令字节 b0 开始。

车道方向来自原厂运行时 `SetDir`，用语言资源顺序覆盖设计器初始列表：0双向、1来向、2去向。3为未支持值，只读展示并禁用写入。原厂停止线输入检查有65535m上限，但编码实际只有16位厘米，本版按655.35m防溢出；同样不接受精度截断、NaN或无穷值。

工作流程：点击 → 校验 → 从当前连接读取原值 → 日志写入意图 → 发一次设置 → 后台等待约3秒 → 再读取 → 比较。预读失败不设置；断线不把命令转发给新连接；设置中不允许启动雷达保存；设置异常不自动重试，提示设备可能已改动并要求读回核对。日志保存于选定雷达数据目录/device-settings。

`RadarParameterTests` 对照真实厂家 DLL 的解码回调，验证大小端、负数、两组车道位域；本地 TCP 模拟验证拆包、异组回复、错误雷达编号、读回不一致、预读超时、断线和录制期间写入拦截。真实固件接受范围、灵敏度效果和断电持久化尚未验证。
